2026-05-22

中国AI调用量首超美国2.11倍

国产模型 调用量 AI应用

事件：5月4日-10日，中国AI周调用量达7.94万亿Token，美国为3.76万亿，中国首次以2.11倍优势领先；DeepSeek三款模型总调用量首超OpenAI全系产品之和。

事件梳理

  • 关键数据：中国周调用量7.94万亿Token vs 美国3.76万亿，比例达2.11:1
  • 价格优势：DeepSeek定价$0.02/百万Token，仅为GPT-5.5（$3.4）的1/170
  • 趋势延续：此前5月11-17日数据显示中国调用量为美国1.81倍，连续三周保持领先且差距扩大

我的分析

1. 对行业格局意味着什么？谁是赢家/输家？

竞争是动态过程，没有恒定赢家。国产模型现阶段凭借极致性价比占据优势，但各方仍在激烈角逐中。最终格局将是几个头部玩家并存——谁能在成本、性能、生态之间找到最佳平衡点，谁就阶段性领先。

成本下降是模型普及的必经之路，国产模型现在走在前面。但长期来看，技术迭代和生态建设才是护城河。

2. 如果你是产品经理，会如何抓住这个机会？切入点在哪？

先打"性能要求没那么严格"的场景：

  • 客服自动化（响应速度>推理深度）
  • 内容生成（营销文案、电商描述）
  • 数据分析（结构化数据提取、报表生成）

用成本优势换市场份额，在这些领域国产模型完全够用，且成本只有国外模型的1/100甚至更低，利润空间巨大。

3. 对普通用户/企业有什么实际影响？现在该做什么准备？

  • 普通用户：主动学习AI相关知识不掉队。AI素养和当年电脑/互联网一样，成了基础能力。无论工作、生活还是投资，懂AI和不懂AI的差距会越来越大。
  • 企业：积极将工作流融入AI，降本增效。这不是"要不要做"的问题，是"怎么做更快"的问题。先从标准化、重复性高的环节切入，逐步扩展到核心业务。

总结：调用量反超不是终点，而是新一轮竞争的开始。国产模型的性价比窗口期有限，窗口期内把应用层做扎实、把用户习惯培养起来，才是护城河。

谷歌的战略转向——从模型竞赛到Agent落地：

2026-05-15

ChatGPT份额失守：Anthropic如何用"企业深耕"撬动AI格局重塑

AI竞争格局 企业市场 Claude

主题：OpenAI vs Anthropic 竞争格局分析

我的分析

企业市场的天平正在倾斜

2026年，AI行业最值得关注的变化不是某款新模型发布，而是一场静悄悄的企业客户迁移：Anthropic首次在企业市场超越OpenAI。这不是偶然，是两种商业逻辑长期分叉后的必然结果。

从数据看，Anthropic企业份额从2023年的12%飙升至2025年底的40%，同期OpenAI从50%跌至27%。更说明问题的是：财富10强中8家把Claude作为主力AI供应商，年消费超100万美元的企业客户从500家增长到1000家只用了两个月。Claude Code在8个月内做到25亿美元ARR——这还是GitHub公开commit中只有4%由它生成的情况，一个月前这个数字是2%，增速惊人。

两种模式的本质差异

这场对决背后是两种截然不同的商业哲学。

OpenAI走的是流量平台模式：先在C端跑马圈地，ChatGPT周活9亿，但付费率不到6%（约5000万）。为了覆盖算力成本，开了订阅、广告、浏览器Atlas、AI硬件多条线，越来越像一家互联网公司。3月推出GPT-5.4 Nano主打成本效率（$0.20/百万token），本质是用规模换经济性，在高频低复杂度场景赢。

Anthropic则选择企业深耕模式：企业+开发者收入占比超80%，不做广告。Claude Code是关键武器——它不是聊天工具，而是能读整个代码库→规划→写代码→运行→评估→迭代的完整Agent。这种agentic产品定位，精准切中了企业"需要一个能干活的员工而非能聊天的助手"的核心需求。

Zero Data Retention：不只是噱头，是护城河

Anthropic还有一个被低估的杀手锏：Zero Data Retention（零数据留存）。

具体来说：API请求在内存中处理，返回结果后立刻销毁，不写日志、不存磁盘、不留备份，连session ID都不留。这意味着理论上即使被法院传票也无可交数据。对法律、医疗、金融行业来说，这是刚需——律所客户信息留存违反律师-客户特权，医疗机构患者数据留存触发HIPAA违规，金融机构交易策略外泄更是致命风险。

OpenAI在Azure上也有类似功能，但需要企业协议+单独申请审批，门槛高得多。Anthropic的ZDR直接覆盖API和Claude Code（网页版聊天不在范围内），服务更聚焦。这解释了为什么财富10强里8家选Claude——合规刚需面前，ZDR不是加分项，是入场券。

Salesforce、Slack、Jira的启示：市场必然分层

拿这三家企业类比当前AI竞争格局很贴切：

千Tokens/s推理突破：当广度优先搜索重新定义AI思考方式

推理速度 广度优先搜索 MoE模型

事件：小米MiMo-V2.5-Pro-UltraSpeed版本在万亿参数MoE模型上实现单节点千Tokens/s推理速度，引发对AI推理范式转变的讨论

事件梳理

  • 技术突破：小米发布MiMo-V2.5-Pro-UltraSpeed版本，万亿参数级MoE模型实现1000+ tokens/s解码速度
  • 实现路径：FP4量化（仅MoE专家部分）+ Flash投机解码 + TileRT软硬协同设计
  • 硬件要求：仅需单台8-GPU商用节点即可运行
  • 商业定价：API价格为标准模型的3倍，但速度约10倍

我的分析

1. 什么是广度优先搜索（BFS）

广度优先搜索（Breadth-First Search, BFS）是图/树结构的经典遍历算法——先遍历当前层的所有节点，再向下一层推进，而非沿着单一路径一直走到黑。与之相对的是深度优先搜索（DFS），即沿着一条路径不断深入，走不通了才回溯。

当前大模型推理 ≈ 深度优先搜索（DFS）：模型沿着一条思路链式推进（Chain-of-Thought），一步步往下推导。受限于推理速度和成本，通常只沿着一条主路径思考。

推理速度提升10倍 → 可以玩广度优先搜索（BFS）：同一时间并行探索多条推理路径，每条路径走几步后评估，挑出最优路径继续深挖。好比同时派出10个侦察兵从不同方向找路，谁找到最优解就集中资源跟进。

2. 两种推理范式的适用场景

范式 核心特征 典型适用场景
链式推理（DFS） 单路径、深思考、强逻辑 数学证明、代码调试、法律文书、严谨推理类任务
广度探索（BFS） 多路径、广覆盖、择优收敛 战略规划、方案选型、旅游攻略、创意生成、决策推演

3. 对产业格局的影响

表面上看利好头部厂商：头部拥有更多算力资源和更深的技术积累，更多算力=能同时探索更多路径=BFS效果更好。但深入想一层，竞争维度可能发生根本变化。

BFS范式下，比拼的不再只是单条推理链能跑多深（参数规模、上下文长度），而是单位时间内能并行探索多少条路径以及多快能从多条路径中筛选出最优解。单模型能力不再是唯一护城河，工程化效率的权重上升。

4. 哪些应用会率先受益？

  • AI Agent — 持续运行、多工具调用的智能体需要大量推理token，成本下降后可真正24/7运行
  • 实时多模态交互 — 视频理解、实时对话、动态场景分析等需要高吞吐的场景
  • 千人千面定制化服务 — 每个用户/每个场景都跑独立推理路径的个性化服务
  • 仿真推演 — 多情景模拟、战略推演、风险评估等需要并行探索多种可能性的场景
  • 创意生成 — 同时生成多个创意方向再择优深化

总结：千Tokens/s推理速度突破不只是性能数字的提升，更可能触发AI产业的底层范式变革。BFS推理模式下，竞争维度从"模型深度"转向"推理效率×搜索算法"，头部厂商有优势但并非不可挑战。

  • 全局+局部混合：少数关键token保留全局视野，其余局部（Longformer/BigBird思路）
  • Token选择/过滤：动态判断哪些token值得计算，不重要的跳过（MiniMax M3大概率属此类）

代价与边界：信息被"稀疏"掉的风险——精确逐字匹配场景（法律合同、金融报表、代码逻辑链）可能丢失关键信息；选择机制本身有计算开销，策略不佳反而得不偿失；"Needle in a Haystack"类任务敏感——关键信息恰好被跳过就出问题。

3. IPO对技术路线的影响

资本追求可量化的增长指标，而基础架构研究（如稀疏注意力边界突破）往往3-5年未必有商业回报。科创板虽有"核心技术"要求，但市场更看重营收增速。IPO后能否保持对长期技术投入的战略定力，是关键变量。

总结：稀疏注意力是效率与精度的权衡，不是免费的午餐。IPO是把双刃剑——带来资源但也可能压缩技术探索空间。

GitHub Copilot按量计费与AI工具定价逻辑

AI定价 按量计费 AI工具

事件：GitHub Copilot由固定月费调整为token按量收费，部分开发者月费从29美元飙至近750美元

事件梳理

  • 调价内容：6月1日起，Copilot由订阅制改为token按量计费
  • 价格冲击：部分开发者月费从29美元暴涨至近750美元，引发社区强烈反应
  • 背景原因：Vibe Coding模式下token消耗远超预期，订阅制无法覆盖成本

我的分析

1. Vibe Coding导致token过度消耗的三层原因

  • 模型层：不同大模型在同等任务下token消耗差异显著，部分模型推理过程本身就非常"话多"
  • 框架层：部分Agent框架无法很好地理解和执行任务，需要反复调试、多轮修正才能完成目标
  • 使用者层：使用AI coding工具是有技巧的，最好在开始coding之前先与Agent共同制定详细需求和开发框架

2. 订阅制vs按量计费：不是非此即彼，而是按场景分化

  • 订阅制适合：聊天类、token消耗低、面向大量普通用户日常使用的工具。一价全包，简单直接
  • 按量计费适合：专业性强的工具（如AI coding）、领域专用AI工具、对算力消耗大的场景

3. AI coding产品在试探定价锚点

Copilot这波调价，与其说是"AI工具补贴时代终结"，不如说是AI coding产品在试探自己的定价锚点：代码补全等高频低价值场景会被挤出付费区间，变成开源/免费的战场；Agent式自主编程更能justify按token收费，因为产出明确、用户愿意为结果买单。

总结：按量计费不是Copilot的独角戏，而是AI工具定价逻辑从"补贴获客"走向"价值定价"的拐点。
